# 04 · 写阶段性复盘（原语 / primitive）

## 说明

**角色**：文档原语，供 [00-govern-orchestrator.md](00-govern-orchestrator.md) 调用；也可高级直调。默认用户路径请用编排器。

解决「阶段结束了却没有结论，或复盘写成表扬稿」的问题。  
引导 AI 基于 `00-meta` / `01-decision` / `02-execution` 的**已有事实**，在 `03-audit.md` 写出成果、偏差、改进与结论。

---

## 提示词正文

```markdown
你是本项目的目标治理协作者。遵守项目 AI 规则（根 `AGENTS.md` 和/或 `.github/copilot-instructions.md`）。

## 任务
为指定目标撰写或追加**阶段性复盘**，写入 `03-audit.md`。复盘必须锚定已有文档中的事实，禁止编造成果。

## 用户输入
如果某项信息缺失或不确定，请先向我确认，不要猜测后继续。
- 目标 ID / 路径：【如 GOAL-003-skills-practice】
- 复盘区间：【如 2026-07-18 ～ 2026-07-25，或「立项至首次 Skills 落地」】
- 复盘类型：【中期检查 / 阶段结束 / 目标关闭】
- 你认为的主要成果（可空，让 AI 从文档归纳后你再确认）：【可选】
- 已知偏差或问题：【可选】
- 是否因此调整 status/progress：【否 / 是，说明】
- 今日日期：【YYYY-MM-DD】

## 强制步骤
1. 通读该目标：
   - `00-meta.md`（成功标准、范围、progress）
   - `01-decision.md`（关键取舍）
   - `02-execution.md`（时间线事实）
   - 现有 `03-audit.md`
2. 对照成功标准，逐条判断：已达成 / 部分 / 未开始 / 证据不足。
3. 在 `03-audit.md` 追加一节（保留历史复盘，不要覆盖掉旧章节）：

   ## A-NNN · <复盘标题>（YYYY-MM-DD）
   ### 范围与区间
   ### 成果（有证据）
   - ……（指向具体文件、决策编号或 execution 条目）
   ### 对照成功标准
   | 标准 | 状态 | 证据 |
   |------|------|------|
   | … | 已达成/部分/未开始 | … |
   ### 偏差与问题
   - ……
   ### 根因（简要）
   - ……
   ### 改进措施（可执行）
   - [ ] ……
   ### 结论
   - 一句话结论 + 建议的下一步（继续 / 收窄范围 / 关闭 / 升级为新目标等）

4. 编号 A-001 起递增；更新 frontmatter `updated`。
5. 改进措施若已决定立刻执行：
   - 可在 `02-execution.md` 记一条「复盘 A-NNN 后的跟进计划」（计划项）
   - 若形成正式取舍，另用决策提示词写入 `01-decision.md`，不要把重大决策只写在 audit 里
6. 若复盘结论是目标 `done` / `cancelled` / 进度大变：
   - 更新 `00-meta.md` 的 status、progress、updated
   - **必须**同步 `docs/goals/goal-tree.md`
7. 语气要求：具体、可验证、可改进；避免「非常顺利」「圆满完成」等无证据形容词。

## 禁止
- 禁止在证据不足时勾选成功标准为完成
- 禁止删除或篡改历史 execution 来「配合」复盘结论
- 禁止跳过 goal-tree 直接改 status
- 禁止把复盘写成与文档事实矛盾的总结

## 交付检查清单
- [ ] 复盘有编号与日期
- [ ] 成果均能对应到文档证据
- [ ] 成功标准对照表完整
- [ ] 改进措施可执行
- [ ] 如有 status/progress 变更，meta 与 goal-tree 已同步
```

---

## 使用注意事项

- 中期复盘不必强行关闭目标；结论可以是「继续，但收窄范围」。
- 若材料不足，应让 AI 列出「证据缺口」而不是脑补成果。
- 目标正式 `done` 前，建议至少有一次阶段复盘（A-00x）沉淀结论。
