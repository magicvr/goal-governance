# 决策记录 · GOAL-003

## D-001 · 优先完善 Skills，再推进 Web 数据能力

**决定**：在 GOAL-002 初始化完成后，下一阶段优先完善 Skills（规则模板、提示词、目标文件夹示例）并在本项目中实践验证，而不是先做 Web 数据模型 / CRUD / 校验工具。

**为什么**：

- **文档是 source of truth**：Web 与 AI 都依赖同一套目标文档；规则不清时，先做界面只会放大漂移。
- **协作立刻受益**：人与 AI 每天都在写 meta / decision / execution / audit；更清晰的 Skills 能马上降低结构错误与虚构进度。
- **成本更低、闭环更快**：完善模板与提示词可在文档侧快速迭代；Web 联动依赖稳定约定，过早开发易返工。
- **GOAL-002 审计已指向此方向**：bootstrap 收尾明确建议用新子目标承接 Skills 深化，避免继续堆在初始化目标里。
- **实践验证才算交付**：仅有空模板不够；在本项目强制使用并留下反馈记录，才能证明 Skills「可执行」。

**未选方案**：

| 方案 | 未选原因 |
|------|----------|
| 先做 Web CRUD / 读 `docs/goals` | 规则与模板未打磨时，数据映射与 UI 字段容易反复改 |
| 先做自动化校验工具 | 校验依赖约定稳定；当前更缺「怎么写」而不是「怎么查」 |
| 先做可安装 Skill 包 | 打包前应先把内容与工作流跑通，否则安装物会过早固化半成品 |
| 把 Skills 工作继续塞进 GOAL-002 | 会模糊「初始化完成」边界，与 bootstrap 成功标准冲突 |

## D-002 · 本目标交付物形态

**决定**：以「可复制文件 + 使用反馈文档」为主交付，不绑定特定 IDE 安装格式。

**为什么**：

- 与 GOAL-002 已建立的 `skills/` 结构一致，便于其他项目复制启用。
- 反馈记录沉淀在本目标（文档或 `attachments/`），形成可审计的改进闭环。
- 为后续「可安装 Skill 包」子目标保留清晰前置条件。

## D-003 · 本仓库强制使用与模板同步

**决定**：本仓库继续以根目录 [AGENTS.md](../../../AGENTS.md) 为生效规则；`skills/AGENTS.template.md` 为可复用模板。规则变更时两者应对齐，并在执行记录中注明。

**为什么**：

- 避免「模板改了、仓库实际规则没改」的双源不一致。
- 实践验证发生在本仓库，必须先保证本地规则可执行。
