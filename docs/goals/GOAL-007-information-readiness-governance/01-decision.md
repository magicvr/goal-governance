# 决策记录 · GOAL-007

## D-001 · 采用 P-005「信息就绪与未知项门禁」

**状态**：accepted

**决定**：核心闭环新增 P-005。目标可在存在未知信息时创建，但必须登记 `required`/`non-blocking` 级别、影响、最晚需要阶段、验证动作、状态、延期复核和证据；影响某门禁的 `required` 未知在该门禁前必须被验证，或由用户书面接受残余风险。有界实验只能进入明确的信息收集范围，信息项保持 `collecting`。未经处理的 required 未知不得被写成既定事实、不得放行受影响阶段、不得用于关门。

**为什么**：

- P-001 处理“如何拆分”，P-002 处理质量审视和整改，均没有表达“还必须知道什么、何时必须知道”。
- 不能证明立项时已知“所有”信息；可治理的是已识别的未知、假设及其发现后的回流路径。
- 将信息项与证据、决策和审计关联，能让范围或验收因新信息变化时有可追踪的修正依据。

**未选方案**：

- 仅靠后续审计发现信息缺口：暴露过晚，且无法表达规划或实施前的必需知识。
- 强制所有目标在立项时先完成全部信息收集：会阻塞本就以探索为目的的目标，也会伪造确定性。

## D-002 · 信息澄清与信息收集按规模拆分，而非自动创建两个子目标

**状态**：accepted

**决定**：先在父目标的 `00-meta.md` 或 `01-decision.md` 建立信息需求清单与阶段门禁。只有当澄清或收集工作具有独立范围、依赖、交付证据或并行价值时，才创建“信息澄清/验证”或“信息收集”子目标；低风险、可逆且可在同一小目标内解决的未知保留在登记表与检查点中。

**为什么**：

- 保留用户提出的两类工作：先识别需要知道什么与何时需要，再收集证据。
- 避免把每个问题机械编号成两个子目标，符合 P-001 的“先路线图、后按阶段立项”。

**未选方案**：每次立项后无条件创建两个子目标。该方案会在信息尚未分类前过早承诺结构，并制造不必要的目标树噪音。
