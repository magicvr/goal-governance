# 决策记录 · GOAL-005

## D-001 · 以新目标承接 Skills 闭环升级（不重开 GOAL-003）

**日期**：2026-07-18  
**状态**：accepted

**决定**：

将「编排器闭环加深 + 交叉审计」立为 [GOAL-005-skills-closed-loop-audit](00-meta.md)，`parent: GOAL-001-main-vision`。不重开、不扩写已关门的 GOAL-003 结项标准。

**为什么**：

- GOAL-003 成功标准是单入口 + 原语 + 安装地基，已审计关门；扩写会污染历史边界。
- 本次是新能力范围（门禁意识、交叉审计、意见台账式响应），应可独立追踪与复盘。
- 与 GOAL-004（数据/Web）并行，避免塞进错误交付线。

**未选方案**：

- **重开 GOAL-003**：破坏 done 语义与 A-00x 历史。
- **并入 GOAL-004**：领域不同，双线纠缠。
- **只改文件不立项**：讨论结论无法进入目标真相源。

## D-002 · 目标态生命周期：质量门禁 + 修正环（简化落地）

**日期**：2026-07-18  
**状态**：accepted

**决定**：

以「设立目标 → 目标质量审视 → 方案与计划 → 设计/计划审视 → 实施并记事实 → 事实审计（含整改环）→ 关门审计」为**目标态**闭环。落地时允许按目标大小比例裁剪（小目标可合并审视），但编排器应具备门禁与修正意识，而非仅「填下一张表」。

**为什么**：

- 当前 `/govern` 擅长推进文档，缺少「阶段是否有资格进入下一阶段」。
- 设立时即可能目标偏移；仅对执行做事后复盘不够。
- 整改应走「方案/计划 → 再审 → 再实施 → 再审」，避免只写改进空话。

**未选方案**：

- **维持纯线性「设立 → 推进 → 偶尔复盘」**：无法对齐质量治理预期。
- **首版即上全自动状态机 + 硬编码全部门禁**：过重，先原则与提示词最小闭环。

## D-003 · 交叉审计独立入口；响应闭环在编排器

**日期**：2026-07-18  
**状态**：accepted

**决定**：

- **独立审计入口**（如 `/audit`）：用于交叉审计，降低同一编排闭环内的自证幻觉；默认**只出审计意见**，不直接改目标 status/progress/方案正文。
- **编排器 `/govern`**：推进生命周期；**汇总并响应全部相关审计意见**（自审 + 一次或多次独立审）；驱动修正、复审邀请与放行。
- 独立审计可多次介入；修正后可再次交叉复审。

**为什么**：

- 同一会话「自写自审自 pass」易产生自证幻觉。
- 出意见权威与改状态权威适度分离；关门与状态变更仍由编排器 + 用户确认。
- 响应若放在独立入口，会变成第二编排器，状态易分叉。

**未选方案**：

- **不做独立入口、只加强自审**：交叉动机落空。
- **独立入口自己改状态并关门**：破坏单一生命周期所有者。
- **再做一个与 `/govern` 平级的完整第二编排器**：产品面回潮。

## D-004 · 是否自审：有独立无自审时询问用户（不自动跳过）

**日期**：2026-07-18  
**状态**：accepted

**决定**：

当编排器发现**已有独立审计意见、尚无自审计**时：**询问用户**是否还需要自审计，由用户决定；**不**自动判定跳过或强制自审。

复杂机制（对象 revision 指纹、覆盖度自动判定、strict 档强制 independent 等）**明确延后**。

**为什么**：

- 自动 skip 条件机过早引入会增加错误放行与实现复杂度。
- 用户裁决简单可预期，与当前 Skills 成熟度匹配。

**未选方案**：

- **有独立意见即自动跳过自审**：省事但易误用过时/范围不匹配的意见。
- **永远强制自审 + 独立审**：对小目标过重，且仍应允许用户选择。

## D-005 · 多审计意见冲突：提示用户决策并给出建议

**日期**：2026-07-18  
**状态**：accepted

**决定**：

当多条审计意见在结论或必改项上**明显冲突**时，编排器：

1. 不静默合并、不自动取更乐观/更悲观一侧；
2. 展示冲突摘要（来源、编号、verdict、关键差异）；
3. **给出建议**（附简短理由）；
4. **等用户决策**；采纳/驳回/折中须留痕（decision 或等价记录）；
5. 未决策前不因「已有审计」而放行下一阶段或关门。

可叠加、同向的多条 fail 不视为冲突，合并为开放意见集合响应即可。

**为什么**：

- 冲突静默裁决等于隐藏治理；用户才是最终责任人。
- 建议降低决策成本，但不替代确认。

**未选方案**：

- **默认保守自动取 fail 侧且不询问**：少问一句，但用户失去显式授权与留痕。
- **默认取最新一条意见**：时间不等于正确。

## D-006 · 产品面：主入口仍为 `/govern`；`/audit` 为交叉专用

**日期**：2026-07-18  
**状态**：accepted

**决定**：

默认产品面保持**单一主入口 `/govern`**。交叉审计为独立能力入口（命名以落地时为准，倾向 `/audit`），不与四个历史填表原语并列为主路径。01–04 仍为原语；`04` 按需增强结构。

**为什么**：

- GOAL-003 已纠正「四入口并列」偏差，不得回潮。
- 独立入口语义是「审查」，不是「再选一张表」。
