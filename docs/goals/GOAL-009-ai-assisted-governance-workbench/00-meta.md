# GOAL-009 · 规划 AI 协助的人类目标治理 Web 工作台

## 概述

定义一个供人类实际推进目标、并由 AI 提供可审查协助的 Web 工作台形态。它不是 Markdown 浏览器，也不是由 AI 自主决定或维护状态的代理。`docs/goals/` 继续保存唯一的运行时事实；工作台的价值在于让人能够理解上下文、提出和审查治理动作、确认受控变更，并追溯证据。

## 初始成功标准

- [ ] 明确目标负责人、协作者和审计者的核心工作流，以及第一个最小可验证使用场景。
- [ ] 定义 AI 的职责、可见上下文、建议输出、引用方式和人类确认边界，明确不得自动裁决 P-004、关闭 required finding 或标记 `done`。
- [ ] 定义 canonical 读模型、历史记录显示规则和受控写入的提案、diff、确认、事务、恢复与证据要求。
- [ ] 完成 AI、身份/授权、数据处理、部署和故障安全的信息就绪判断，并将影响实现的 required 项与最晚阶段写清。
- [ ] 形成阶段 6 高层路线图和第一个实现子目标的立项条件；不提前批量拆分或把计划当作已实现功能。

## 产品定位与已知工作流

1. **日常推进**：目标负责人从工作台看到目标树、当前门禁、最近事实和关联证据；AI 基于引用的 canonical 记录提出下一步与需要人裁决的问题。
2. **方案与执行审查**：人和 AI 共同把目标上下文转为可编辑的决策、计划或执行候选；用户比较影响、修订内容并明确确认后才进入受控变更路径。
3. **审计与关门**：审计者查看 self/independent 意见、开放 finding、信息门禁和证据；AI 可以整理差异和缺口，但不能自动放行或关门。
4. **受控变更**：人选择创建或更新目标、决策、执行或审计记录时，系统必须呈现结构化提案和 diff，记录操作者与确认，并以五件套和 `goal-tree.md` 的同一协议完成或回滚写入。

## 边界

- 不把“只读 Web”作为阶段 6 成功标准；现有页面只是可复用的基础。
- 不建立独立状态数据库或以 AI 输出替代 canonical 文档。
- 不在本目标中直接开放无确认写入、自动关门、自动 P-004 裁决、生产部署或批量实现子目标。
- 后续实现应按已冻结的最小工作流立项；信息收集与设计事实留在本目标，实际代码交付留在后续目标。
