# 决策记录 · GOAL-009

## D-001 · 以人机协作工作台而非只读浏览器为产品方向（2026-07-20）

**状态**：accepted

**确认来源**：用户明确要求 Web 服务于“人类工作时有 AI 协助”的目标治理，而非完善纯只读页面。

**决定**：

1. GOAL-009 规划的产品是人类主导、AI 协助的治理工作台。AI 应把 canonical 目标记录转化为有引用的上下文、候选下一步、候选文档变更和风险提示；人保有审查、编辑、拒绝、确认和裁决权。
2. 受控写入属于产品方向，但不是本轮实现承诺。任何写入须经过结构化提案、可读 diff、明确确认、协议验证、可恢复事务和可追溯的审计证据。
3. `docs/goals/` 与 `goal-tree.md` 继续是唯一运行时真相。工作台可消费和受控更新它们，但不建立第二套状态、生命周期或“AI 已完成”标记。
4. 每个 required 信息项只阻断其影响的阶段：I-001 阻断产品方案冻结，I-002 阻断 AI 接入，I-003/I-004 阻断首个 Web 写入，I-005 阻断部署或外部访问，I-006 阻断端到端验收。它们不阻断本目标的产品发现，也不要求机械等待所有项关闭后才可按已明确的最小范围立项。

**为什么**：

- 读取 Markdown 本身不能替代目标设立、决策、执行、审计与响应工作；用户需要的是更好的治理动作能力。
- 现有文档协议和 `GoalsRepository` 的事务基础可以成为可信协作面的起点，但尚不足以安全地暴露给人或 AI。
- 将人类确认和证据作为产品核心，既避免 AI 自主越权，也避免“只读”成为逃避设计真实工作流的借口。

**未选方案**：

- 把阶段 6 收敛为树浏览、Markdown 呈现和诊断打磨：价值与直接阅读文档重叠，不能推进实际治理。
- 直接把现有 service 写方法暴露为 Web/AI API：当前缺少身份、授权、确认、溯源、并发和安全失败机制。
- 让 Web 或模型维护独立状态：会违背 canonical 文档真相源并造成同步漂移。

**影响与后续**：本决定引用根 D-014。I-001～I-006 的收集结果将决定第一个实现目标的边界；本轮不宣称任何产品功能或安全控制已完成。
