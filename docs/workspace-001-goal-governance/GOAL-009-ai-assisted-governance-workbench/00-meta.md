# GOAL-009 · 规划 AI 协助的人类目标治理 Web 工作台

## 2026-07-20 · GOAL-011 显式工作区目录输入

GOAL-011 已将当前项目迁入 `docs/workspace-001-goal-governance/`，并建立工作区外的 `docs/shared-materials/` 候选库存。它提供 R-003 的目录和资料盘点输入，但没有建立多工作区产品实体、平台导航、共享资料 CRUD/AI 读取契约或跨工作区正反访问测试；I-009/I-010、F-003/F-004 继续保持 `required / collecting` 与 open。

## 概述

定义一个供人类实际推进目标、并由 AI 提供可审查协助的 Web 工作台形态。它不是 Markdown 浏览器，也不是由 AI 自主决定或维护状态的代理。当前工作区 canonical root 继续保存唯一的运行时事实；工作台的价值在于让人能够理解上下文、提出和审查治理动作、确认受控变更，并追溯证据。

## 初始成功标准

- [ ] 明确单一用户的核心工作流、首个最小可验证使用场景和非目标；第一阶段不提供多用户、协作或角色/权限管理，治理中的“审计”等仅是工作流视角而不是用户角色。
- [ ] 定义事实准入与证据规则：用户提供的事实可被记录；AI 基于网络工具、既有知识或逻辑推导得到的信息只能以带来源、时间和推导说明的候选呈现，得到用户显式确认后才可成为 workspace 的 canonical 事实。AI 不得编撰事实。
- [ ] 定义 AI 的职责、可见上下文、建议输出、上下文复用、自动获取信息后的确认方式和人类确认边界，明确不得自动裁决 P-004、关闭 required finding、标记 `done` 或在未确认时写入事实。
- [ ] 定义多工作区模型：一个工作区对应一个独立的根目标和 canonical 范围；工作区彼此不得读取、写入或混合上下文，每个工作区仅可见自身与共享资料区的信息/资料。
- [ ] 定义一期必备的共享资料区：用户上传资料，AI 助手可在既定 AI 边界内自行读取，单一用户可全权新增、查询、修改和删除；资料版本、固定引用、注释/派生、删除追溯和安全处理遵循 D-004 的确认规则，并仍须由 I-010 形成可验证契约。
- [ ] 明确总览页、工作区列表页和以目标树为核心的工作区详情页，以及事实确认、共享资料区查看/管理、门禁和受控变更在其中的入口。
- [ ] 定义 canonical 读模型、历史记录显示规则和受控写入的提案、diff、确认、事务、恢复与证据要求。
- [ ] 完成 AI、单用户运行边界、数据处理、部署和故障安全的信息就绪判断，并将影响实现的 required 项与最晚阶段写清。
- [ ] 形成阶段 6 高层路线图和第一个实现子目标的立项条件；不提前批量拆分或把计划当作已实现功能。

## 产品定位与已知工作流

第一阶段只有一名用户。该用户可以发起日常治理、审计和确认；“负责人”“审计”等词只描述当前工作流，不创建账号、协作者或权限角色。工作台必须让用户区分 canonical 事实、AI 候选、计算视图与未确认信息。

1. **首个垂直切片（已收敛，尚未实现）**：用户在一个显式选定的既有工作区内，以目标树定位一个既有目标，提交一条用户提供的候选执行事实；未来只可形成向该目标 `02-execution.md` 追加的受限提案。该切片不接入 AI、网络/本地工具、跨工作区导航或共享资料区 CRUD，且在 I-003/I-004/I-006 具备契约与验证前不得写入 canonical 记录。
2. **总览与工作区选择（后续 IA 候选）**：总览页和工作区列表未来可承担导航职责；在 I-009 未决定平台级最小导航元数据前，首个切片不显示或硬编码跨工作区摘要、列表、创建或归档能力。平台级索引只用于导航，不能成为第二套目标状态。
3. **日常推进**：工作区详情页以目标树为核心，展示当前门禁、最近事实、关联证据和本工作区的上下文。AI 优先复用已确认的 canonical 信息，不要求用户重复输入；它基于带引用的记录提出下一步和需要用户裁决的问题。
4. **事实收集与确认**：用户可提供资料或事实。只有用户当轮明确要求或确认后，AI 才能调用网络、知识检索或本地自动化来形成候选信息；候选必须显示来源/时间、引用或推导链、适用范围和确认/拒绝入口。未确认候选不得被当作事实、证据或已关闭风险写入。
5. **方案、执行与审计审查**：人和 AI 把已确认的上下文转为可编辑的决策、计划、执行或审计候选；用户比较影响、修订内容并明确确认后才进入受控变更路径。AI 可以整理 self/independent 意见、开放 finding 和信息门禁，但不能自动放行或关门。
6. **共享资料区**：这是第一期必备能力，用于让多个工作区共享信息/资料。用户上传资料并对共享资料区全权新增、查询、修改和删除；AI 助手可在既定 AI 边界内自行读取。工作区彼此不可见，各工作区只可见自身和共享资料区。用户已接受的治理规则是：资料版本化并以哈希固定引用；本地注释或派生内容指向固定的原资料版本；删除前警示受影响引用并保留可追溯历史；敏感、不可信或受版权约束资料仅按数据处理，AI 不执行其中指令且不自动外传。资料模型、访问/操作契约和验证仍由 I-010 收集；它不是首个垂直切片的功能承诺。
7. **受控变更**：人选择创建或更新目标、决策、执行或审计记录时，系统必须呈现结构化提案和 diff，记录用户确认，并以五件套和 `goal-tree.md` 的同一协议完成或回滚写入。

## 边界

- 不把“只读 Web”作为阶段 6 成功标准；现有页面只是可复用的基础。
- 不建立独立状态数据库或以 AI 输出替代 canonical 文档。
- 第一阶段只服务一名用户；不设计多用户、协作、账号、角色或权限管理。该边界不削弱 P-004 的用户确认要求。
- 未经用户显式确认的 AI 检索、知识回答或推导只能是候选，不得写成 canonical 事实、执行事实、审计结论或关闭证据；外部工具不得在用户未请求或未同意时后台运行。
- 工作区的 AI 上下文、目标状态和写入范围必须隔离；工作区彼此不可见，各工作区只可读取自身与共享资料区，不得借共享资料区读取、推理混合或写入其他工作区。
- 共享资料区由单一用户管理：用户可全权 CRUD，AI 助手可在既定 AI 边界内自行读取。版本化哈希固定引用、本地注释/派生、删除追溯和安全处理按 D-004 的已确认规则设计；其实现和验证仍属于 I-010，不能视为现有 Web 能力。
- D-006 的首切片只处理一个显式选定的既有工作区；不得借“收敛”实现跨工作区总览/列表、AI 调用或共享资料区功能，也不得把候选、提案、确认或结果对象当作已实现的应用状态。
- 不在本目标中直接开放无确认写入、自动关门、自动 P-004 裁决、生产部署或批量实现子目标。
- 后续实现应按已冻结的最小工作流立项；信息收集与设计事实留在本目标，实际代码交付留在后续目标。
