# R-003 · 工作区产品映射与共享资料区契约（收集稿）

> 本收集稿响应 A-004 **R-003**（经 A-007 重定义）、A-001 **F-003/F-004**，服务 I-009、I-010，并衔接 I-004/I-006。  
> **D-011**：已接受产品打包/dogfood 分栏，以及导航 **N1**、资料存储 **A（部署旁路）**、F-005 关闭路径 **α** 为设计默认；SQLite 仅允许作非 canonical 结构性索引且**非**首切片必选。  
> **仍不关闭** F-003/F-004；I-009/I-010 仍 `collecting`；非实现、非写入放行。

## 0. 产品打包与 dogfood 分栏（D-011 · 权威）

| 层 | 内容 | 发布物 | 其他项目 |
|----|------|--------|----------|
| **可分发产品** | Web、Skills、方法论/协议/模板、contracts 镜像 | 打包副本 | 可见产品与模板 |
| **消费方运行时** | 各项目/部署自己的 workspace + 可选共享资料 | 不由本仓复制 | 仅该项目数据根 |
| **本仓 dogfood** | `workspace-001-…`、本仓 goal-tree/五件套过程、本仓资料与过程附件 | **禁止**打入发布物 | **不得**自动知悉或加载 |

运行时规则：

1. Skills 只服务宿主项目配置下的工作区；Web 只绑定部署配置的数据根与工作区列表。  
2. 无配置 → fail closed；禁止静默回落开发 monorepo dogfood（开发可用显式开关）。  
3. 「跨工作区可见共享资料」= **同一部署实例内**；≠ 跨安装全局云，≠ 本仓资料外泄。  
4. 契约测试使用合成 fixture，不用本仓真实 GOAL 过程树当客户数据。

本仓路径（如 `docs/workspace-001-goal-governance/`、`docs/shared-materials/`）在文档中仅作 **dogfood 与布局示例**，不是产品唯一数据根。

## 3. 工作区产品模型（I-009）

### 3.1 核心映射

| 概念 | 定义 | 约束 |
|------|------|------|
| `workspace_id` | 稳定 ID（消费方自有，如 `workspace-001-acme`） | 与该工作区 `workspace.md` 的 `id` 一致 |
| `root_goal` | 唯一 `parent: null` Root | 不匹配 → fail closed |
| `canonical_scope` | 该工作区目标树与五件套根 | **唯一**目标状态真相；非 SQLite/平台 DB |
| 部署 `data_root` | Web/服务配置的数据根 | 可含多个 workspace 目录 + 实例共享资料根 + 可选结构库 |

### 3.2 导航默认：**N1**（D-011）

| 允许字段 | 禁止 |
|----------|------|
| `workspace_id`、显示名、`root_goal` id、可选 `active\|archived` | 他区目标树/正文/finding/候选/AI 草稿/资料正文/progress 权威副本 |

- 列表范围 = **实例配置内**的工作区，不是本仓 dogfood 扫描。  
- 进入详情 → 从该工作区 canonical **重新加载**。  
- **N0** 不取；**N2** 首期不取。

### 3.3 平台索引 vs 真相源

1. 索引至多缓存 N1 字段 + 重建用路径指针。  
2. 索引不可读或与 `workspace.md` 冲突 → 禁止不确定写入；可降级为配置扫描。  
3. **若使用 SQLite 存索引**：见 §6；丢失或脏读不得冒充 canonical。

### 3.4 隔离负向意图（未执行）

| 案例 | 预期 |
|------|------|
| WS-X-READ/WRITE | 跨产品工作区拒绝且不泄漏 |
| WS-DOGFOOD | 默认配置下不能读到开发 monorepo dogfood |
| WS-PACK | 发布物安装后无本仓 GOAL 过程树 |

## 4. 共享资料区（I-010）

### 4.1 D-004 规则（实例内，不可削弱）

用户 CRUD、AI 边界内读取、版本+哈希固定引用、注释指固定版本、删除前引用警示与历史、敏感资料不执行指令不外传——均在**该部署的共享资料根**上生效。

### 4.2 字节存储默认：**方案 A**（D-011）

- 资料文件落在**部署数据根**旁路目录（布局可类比消费方的 `shared-materials/`）。  
- **不是**「发布时从 goal-governance 开源仓拷贝过程资料」。  
- 触发大文件/密钥/多机路径后再评估外置根；对象存储延后。

### 4.3 元数据对象（候选，同 v0.1）

`Material` / `MaterialVersion`（sha256）/ `MaterialRef` / `LocalAnnotation` — 权威校验仍以哈希与固定引用为准；目录清单或 SQLite 目录表仅为辅助。

## 5. F-005 与首实现边界（路径 α · D-011）

首个实现子目标（**关闭 F-005 前仍不创建**；α 为关闭条件）建议范围：

```text
仅：配置选中的单一产品工作区详情（目标树核心）
  + 用户提供候选执行事实
  + 未来受限 append-execution-fact（仍受 F-007/F-008 与 I-003/I-004/I-006）
不含：总览/列表产品化、共享资料 CRUD、AI 调用、本仓 dogfood 绑定
```

## 6. SQLite 与结构性数据（D-011）

| 用途 | 首切片 | Web 更广阶段 |
|------|--------|----------------|
| 目标 status/progress/五件套/审计正文 | **禁止** DB 权威 | **禁止** |
| N1 导航注册/缓存 | 不需要 | **允许** SQLite 或等价，可重建 |
| 资料元数据索引 | 不需要 | **允许**，字节仍在文件系统 |
| ops/receipt 查询 | 文件 receipt 足够 | 可选辅助索引，权威仍可文件复核 |
| R-004 写入路径 | **无 SQLite 依赖** | 写入仍以 Markdown + 文件事务为准 |

原则：SQLite ⊂ 部署数据根；不进发布物；与 canonical 冲突以 Markdown 为准；可重建或 fail closed。
