# 决策记录 · GOAL-010

## 信息需求与阶段门禁

本目标唯一的信息台账位于 [00-meta.md](00-meta.md#信息就绪与未知项)。I-001～I-004 为 required，分别阻断协议冻结、Skills 适配和关门；I-005 是下游 Web/存储实现信息，不阻断本目标的文档协议闭环。

## D-001 · 将工作区与共享资料引用定义为核心协议，并由 Skills 先适配（2026-07-20）

**状态**：accepted

**确认来源**：用户明确要求创建 GOAL-010，将“工作区”和“共享资料区”概念引入核心文档体系，并先在 Skills 体系实现；同时提出同一项目可有 MVP、二阶段、三阶段等串行目标，不应要求起初写出完整 Root Goal 或反复重写它。

**决定**：

1. 工作区是一个独立治理上下文，绑定一个 Root Goal 和其 canonical 范围；它不是 `parent` 层级、审计 `scope`、页面缓存或第二套目标状态。
2. Root Goal 表达稳定目的和高层路线图。可预见的 MVP、二阶段、三阶段等工作作为串行子目标承接；新信息通常更新路线图和创建阶段目标，只有目的、成功边界或战略方向实际改变时才修改 Root Goal 的定义并记录决策。
3. 共享资料区在核心协议中只定义逻辑资料目录和固定引用约束：每项引用必须能标识资料、来源、版本和哈希；工作区本地注释或派生记录指向固定版本。资料内容或引用不能作为读取、推理混合或写入其他工作区目标状态的通道。
4. 先更新 canonical 文档、模板与独立启用路径，再同步 Skills 提示、宿主规则镜像、安装分发与测试。Skills 作为消费适配器，不成为独立协议或状态来源。
5. 本目标不定义共享资料物理存储、用户 CRUD、AI 读取执行、跨工作区导航、Web API 或确认/写入状态机；这些保持为 GOAL-009 I-009/I-010/I-004 及后续实现目标的门禁。

**为什么**：

- P-001 已允许 Root Goal 保持稳定、路线图演进和阶段子目标串行推进；缺的是把该操作规则与工作区边界明确成可复用协议。
- GOAL-009 已确认工作区隔离和共享资料区是产品方向，但当前核心模板和 Skills 没有可跨宿主复用的定义，容易让 Web 设计成为事实上的单一规范。
- canonical 先行可使独立文档使用、Skills 和后续 Web 共享同一边界，并避免把共享资料误写成第二套目标状态。

**未选方案**：

- **只在 GOAL-009 或 Web 中定义工作区**：会让 docs-only 与 Skills 使用者没有规范，也会把未验证的 Web 细节误提升为核心事实。
- **把每个阶段都改写为新的 Root Goal**：丢失同一项目的长期目的和可追溯路线图，且不符合 P-001 的阶段承接方式。
- **把共享资料直接嵌入任一工作区的目标树或附件**：会模糊资料来源、版本和跨工作区边界，容易形成隐式可写状态。
- **先在 Skills 建立独立格式再补 core**：会违反 canonical 优先与镜像不成为第二真相源的规则。

**影响与后续**：D-001 触发 I-001～I-004 的收集与验证。完成后应向 GOAL-009 R-003 记录协议输入和仍未关闭的 Web/物理存储门禁；不得因本决定改变 GOAL-009 status、progress 或 finding 状态。

## D-002 · 以协议、适配与可重复验证完成关门，并交接下游门禁（2026-07-20）

**状态**：accepted

**依据**：用户明确要求完成 GOAL-010 闭环；D-001 的实施产物与本目标执行记录中的 8 项 core 测试、32 项 Skills 测试及 F-018 isolated install 结果均可复核。

**决定**：

1. 将 I-001 标为 `verified`：协议、模板和语义测试共同证明工作区的 Root Goal/canonical 范围绑定、串行阶段规则和无 `docs/workspace.md` 时的隐式单工作区路径。
2. 将 I-002 标为 `verified`：协议和模板定义 `workspace_id`、`material_id`、`source`、`version`、`sha256`、用途与本地记录；缺失/不匹配、目录为 `none` 或来源不可固定均 fail closed，且资料不会成为第二状态源。
3. 将 I-003 与 I-004 标为 `verified`：`/govern`、原语、`/audit` 和宿主规则镜像消费同一协议；canonical/mirror、standalone、安装分发和正反语义测试均可重复执行。
4. 向 GOAL-009 的 R-003 交付协议、模板与 Skills 输入，但不把它们当作 I-009、I-010、F-003、F-004、Web 写入或产品路线图的关闭证据。I-005 保持 `non-blocking / open`，仅由下游目标收集和验证。

**为什么**：D-001 的交付边界是 core/Skills 协议与适配，而不是共享资料物理存储或 Web 产品实现。上述证据已覆盖本目标的 required 信息门禁与成功标准；把下游产品能力混入关门会违反 P-005 和 GOAL-009 的开放门禁。

**未选方案**：

- **等待 GOAL-009 的 Web/资料实现后再关闭**：会把明确排除的下游范围错误变成本目标的 required 工作，并掩盖责任归属。
- **把协议存在直接等同于 Web 门禁关闭**：缺少资料模型、访问/安全契约、用户 CRUD、AI 读取和跨工作区正反验证，不能形成该结论。

**影响与后续**：GOAL-010 关门为 `done / 100%`；[GOAL-009 A-008](../GOAL-009-ai-assisted-governance-workbench/03-audit.md) 只记录协议输入和不放行边界。后续产品实现继续由 GOAL-009 及其后续子目标负责。
