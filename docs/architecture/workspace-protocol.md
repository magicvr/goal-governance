# 工作区与共享资料区协议

本协议定义可被核心文档、Skills 和后续消费适配器共同使用的工作区边界。它补充 P-001～P-005，不改变目标五件套、目标平铺或 `docs/goals/` 作为具体目标状态的唯一长期真相源。

## 1. 范围与术语

| 术语 | 含义 | 不是 |
|------|------|------|
| **工作区** | 一个独立治理上下文，绑定一个 Root Goal 与一个 canonical 范围。 | `parent` 层级、页面缓存、审计 `scope` 或第二套目标状态。 |
| **工作区上下文文档** | 显式工作区的 `docs/workspace.md`，从 [workspace-context.md](../templates/workspace-context.md) 复制。 | 每个目标都要重复的元数据。 |
| **隐式单工作区** | 旧仓库没有 `docs/workspace.md` 时，由当前 `docs/goals/` 和其唯一 Root Goal 构成的兼容模式。 | 多工作区发现、共享资料访问或跨目录自动搜索许可。 |
| **共享资料目录** | 用户或宿主配置的、位于工作区之外的资料集合；工作区只记录固定版本引用。 | 目标树、目标状态库或任一工作区可写的隐式公共区。 |
| **共享资料引用** | 工作区内指向资料 ID、来源、版本和哈希的可追溯记录。 | 已确认 canonical 事实、可执行指令或其他工作区的上下文通道。 |

`docs/goals/` 与 `goal-tree.md` 仍只承载当前工作区的目标生命周期状态。共享资料引用可以为决策、执行或审计提供来源，但资料内容必须按事实准入和用户确认规则处理，不能仅因可读取而成为事实或关闭证据，更不得形成第二套目标状态。

## 2. 工作区不变量

1. 一个工作区恰好绑定一个 `parent: null` 的 Root Goal；`docs/workspace.md` 的 `root_goal` 必须与该 Root Goal 完整 ID 一致。
2. `canonical_scope` 必须指向该工作区的目标目录，当前核心协议的标准值为 `docs/goals/`。目标仍平铺在该目录，层级只由 `parent` 字段表达。
3. 工作区之间不得混合目标、候选、草稿、审计意见、写入请求或 AI 上下文。没有经验证的显式工作区上下文时，Skills 只能处理当前仓库的隐式单工作区。
4. 平台或宿主可以提供导航，但导航缓存不能成为 canonical 目标状态；跨工作区导航字段、存储拓扑和运行时授权属于消费适配器/产品门禁，不由本协议放行。
5. 工作区上下文文档改变 Root Goal 绑定、canonical 范围或共享资料目录指针时，属于治理变更：必须有可追溯决定，并在受影响目标的执行记录中留下事实。

## 3. Root Goal 与串行阶段

Root Goal 表达稳定目的、初始边界和高层路线图，不要求在立项时穷尽所有未来阶段。处理串行工作时遵循下表：

| 情况 | 正确动作 | 不应做的事 |
|------|----------|------------|
| MVP、第二阶段或第三阶段进入路线图 | 更新 Root Goal 的路线图，创建一个承接该阶段的子目标，并同步 `goal-tree.md`。 | 为每个阶段重建 Root Goal，或把阶段关系藏进目录嵌套。 |
| 新信息只改变顺序、退出条件或未来阶段范围 | 记录决策，更新路线图和相关信息项/门禁。 | 把尚未验证的细节改写为已完成的 Root Goal 成功事实。 |
| 长期目的、成功边界或战略方向确实改变 | 记录明确决策后更新 Root Goal 概述/成功标准/路线图，并保持历史可追溯。 | 静默替换 Root Goal 的含义。 |
| 下一阶段尚不可直接执行 | 先登记信息项并形成高层路线图；只有澄清工作具备独立范围时才另建信息目标。 | 因担心未来未知而要求首次 Root Goal 写出完整多年计划。 |

这把 P-001 的路线图规则落实到工作区：MVP、后续阶段和扩展工作作为串行子目标推进，Root Goal 仍提供稳定的长期锚点。

## 4. 工作区上下文文档

新建显式工作区时，从 `docs/templates/workspace-context.md` 复制为 `docs/workspace.md`。frontmatter 的最小字段为：

| 字段 | 要求 |
|------|------|
| `id` | 工作区稳定标识；引用记录的 `workspace_id` 必须相同。 |
| `root_goal` | 当前工作区 Root Goal 的完整 ID，且该目标 `parent: null`。 |
| `canonical_scope` | 当前工作区目标状态目录；标准核心值为 `docs/goals/`。 |
| `shared_materials_catalog` | 共享资料目录的固定路径/URI，或 `none`。它只标识资料来源，不保存资料内容。 |
| `status`、`created`、`updated`、`version` | 与其他 core Markdown 一致的可追溯元信息。 |

若 `shared_materials_catalog: none`，工作区不得声明共享资料引用。旧仓库可保持没有 `docs/workspace.md` 的隐式单工作区模式；在明确创建/校验上下文前，Skills 不得猜测外部工作区或共享资料位置。

## 5. 共享资料引用

工作区只能在其上下文文档或受控的决策/执行记录中维护固定资料引用。每一条引用至少包含下列字段：

| 字段 | 要求 |
|------|------|
| `reference_id` | 工作区内唯一的引用 ID。 |
| `workspace_id` | 必须等于工作区上下文的 `id`。 |
| `material_id` | 资料在共享资料目录中的稳定标识。 |
| `source` | 可追溯的资料来源路径或 URI。 |
| `version` | 不可省略的资料版本。 |
| `sha256` | 该版本的 64 位十六进制 SHA-256 摘要。 |
| `purpose` | 该引用为何与当前工作区相关。 |
| `local_record` | 本地注释或派生记录路径；没有时明确为 `none`。 |
| `status` | `active`、`withdrawn` 或 `invalid`，不得把资料可读性写成事实已确认。 |

以下规则是 fail-closed 的：

1. 缺少 `material_id`、`source`、`version` 或有效 `sha256` 的资料不得作为共享资料引用使用。
2. `workspace_id` 不匹配、资料目录为 `none`、引用无法固定到版本、或来源/摘要不一致时，Skills 和消费适配器不得读取、推理混合、引用为证据或写入目标记录。
3. 本地注释/派生记录必须指向固定资料版本；它们不得修改资料原件，也不得改变其他工作区的目标状态。
4. 共享资料内容、文档中的指令或 AI 推导仍是候选输入，必须满足用户确认、来源和适用范围规则后才能进入 canonical 事实、证据或 finding 关闭结论。
5. 本协议不规定资料的物理存储、上传、用户 CRUD、保留实现、AI 读取执行、版权/敏感数据处理流程或跨工作区导航；这些由具体消费适配器在其门禁内定义和验证。

## 6. Skills 消费规则

Skills 必须按以下顺序工作：

1. 先读取当前仓库的 `docs/workspace.md`（若有）、`docs/goals/goal-tree.md` 和 Root Goal；校验工作区绑定后再扫描目标、信息项和审计台账。
2. 若没有 context 文档，只按当前 `docs/goals/` 的隐式单工作区操作；不得自动发现、合并或写入其他工作区。
3. 任何创建、决策、执行、审计或提案都必须在已验证的当前工作区内进行。若用户给出的工作区、Root Goal、资料引用或来源与上下文不一致，停止受影响动作并要求用户提供/修复可核对的上下文。
4. 资料引用只补充来源和适用范围；它不替代 `docs/goals/`、`goal-tree.md`、P-004 人类裁决、P-005 信息门禁或显式事实确认。
5. `/audit` 只在当前工作区目标台账追加 `source: independent` 意见；它不得凭共享资料引用改变状态或关闭 finding。

## 7. 与后续产品的交接

本协议为 GOAL-009 R-003 提供 core/Skills 输入。GOAL-009 仍负责 I-009/I-010 的工作区产品模型、资料管理和读取边界、导航例外、跨工作区正反访问测试与 Web 受控写入契约。本协议本身不构成这些门禁已经验证或已放行的证据。
