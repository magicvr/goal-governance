# 根因与验证边界

用户报告实际发生过漂移且审计未发现；未提供该实例文件，不能据此断言某条历史审计应为 fail。本次可直接证实的是 Git `81913d2` 中的规则缺口，后续合成实验验证其修正效果。

| 原始出处（81913d2） | 可核对事实 | 漏审机制 |
|--------------------|------------|----------|
| `skills/prompts/04-write-audit.md:66,68,79` | 通读当前目标、按其成功标准与scope核对 | 当前标准若已漂移，可能以漂移后的清单自证 |
| `skills/prompts/05-independent-audit.md:58,80` | 自主通读目标台账，未强制直接父目标正文/原始授权对照 | parent合法不能证明结果贡献仍存在 |
| `skills/prompts/01-create-new-goal.md:70,74` | 创建parent及成功标准，没有父级结果/版本/初始授权映射 | 拆分时无明确贡献基点，后续难比较 |
| `skills/prompts/02-record-decision.md:65` | 改范围/标准后同步meta，未规定实质替换验收需保留前后及真实授权 | 最新meta可能遮蔽原始承诺；accepted标签无法证明用户批准 |
| `skills/prompts/03-update-execution.md:57-72` | 当前目标记事实、勾标准，未强制父级贡献/实际结果比较 | 文档没改但实施改了验收对象也会漏检 |
| `docs/architecture/principles.md` P-006 §6.3 | 主要判定明显反向、否定边界等；合法兼容子集不构成冲突 | “不明显冲突”只判断负向边界，不证明正向贡献和时间连续性 |

修复为 GD-01～GD-08：父级贡献与原始授权→变更批准→当前路线图覆盖→实际交付。self/independent A 均需可复核对照，显著漂移/缺证据阻断受影响门禁。合法阶段子集和授权演进仍允许，不要求子目标独自完成父目标。

实验由 `host-probes.py` 生成隔离消费仓。反例中本地测试均通过，但分别替代验收、只改变实施、换成无关产物；正例保留阶段子集、书面批准的口径变更及仅交付研究样例。正式审计输入仍仅 `/audit workspace-002 goal-020`，不提示关注点/预期结论。语义结果须读实际 A 报告，不能把进程exit0或兼容信封pass当作漂移识别成功。
