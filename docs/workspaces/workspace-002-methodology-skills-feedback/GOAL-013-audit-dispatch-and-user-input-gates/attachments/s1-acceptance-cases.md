# S1 正反例与验收矩阵

这是经 D-003 采纳的后续验收计划，当前未执行新行为验证。编号格式采用已冻结的 D-002 路径 A；代码路径条件仅适用于现有受影响代码，不由本计划额外创建 B 的新接口。凡运行示例应使用隔离 fixture，禁止为了测试把真实已关目标、其他区或用户数据改为 blocked。

| 用例 | 输入 / 条件 | 预期结果 | 证据层 |
|------|-------------|----------|--------|
| C01 | `/audit 002 013` | 唯一绑定本区完整 workspace_id + goal_id，走 Goal audit；不附加 scope | 静态契约 + 入口运行 |
| C02 | `/audit 2 13` | 数值匹配后规范为 002/013，同 C01；无前缀模糊匹配 | 静态契约；代码路径若有则单元验证 |
| C03 | `/vision-audit 002` | 唯一匹配 VP 文件，走 VRev 台账，不写 Goal audit | 静态契约 + 入口运行 |
| C04 | 合法命令后附“仅审 S2/只看这些文件/请给 pass” | 自动派发拒绝，不截断后发送，不改写成温和建议再发送 | 静态反例 + 实际载荷核对 |
| C05 | system/agent description/context/file/stdin 另加审计限制；fork 复制编排历史 | 不得绕过仅命令要求；自动审计用干净上下文，只承载正式入口标准规则 | 载荷与上下文边界核对 |
| C06 | 多行、注释、JSON 包裹、shell 链、模板未替换、符号/负数/0/小数/科学计数法 | 拒绝并说明；不执行外部命令、不推定目标 | 静态契约；代码路径若有则单元验证 |
| C07 | 不存在、重复数字编号，或目录与 frontmatter id 不符 | 停止解析，不任选、不读取候选目标正文后混合推理 | 隔离 fixture / 入口运行 |
| C08 | 新旧布局混合、非法治理根、仓外/符号链接逃逸 | fail closed，保留原边界 | 既有回归 + 必要新增 fixture |
| C09 | provider 不支持加载正式入口/错误路由/失败/超时 | 门禁未满足；不自编提示代替入口、不冒充 independent | 负例 / 载荷记录 |
| C10 | 人类直接表达审计关注点 | 不扩大为禁止人类指定关注点；自动派发不得伪装成人类直调 | 角色与来源契约 |
| U01 | 当前可用且允许的同步询问卡片 | 展示原问题，暂停；实际提交后才处理答案 | 当前宿主实际交互 |
| U02 | `{}` / `[]` / 空白 / null / 缺问题答案 | 记录未答；暂停任务；有当前 active/draft Goal 则 blocked + 树同步；无默认选择 | 隔离问答记录 + 结果核对 |
| U03 | cancel/dismiss/timeout/卡片仅展示成功 | 与未答相同；不按取消解释为“否决方案”或“接受残余” | 隔离问答记录 + 宿主实测 |
| U04 | UI 预选但用户未提交 | 继续等待，不构造提交事实 | 真实 UI；静态规则仅防漂移 |
| U05 | 卡片不可用、headless、工具被禁用/用途不允许 | 文本提问，持久待答并停止；不使用异步调用后继续实施 | 各运行模式核对 |
| U06 | 多问题只收到部分答案/答非所问 | 保存真实部分答案；未答部分保持等待、相关门禁未满足 | 问答记录 + 结果核对 |
| U07 | 已有另一个阻塞原因 | 追加待答原因，不覆盖原阻塞；真实答复只解除对应原因 | 隔离 Goal fixture |
| U08 | 无当前 Goal / 只有 VP | 暂停任务并保存待答；不新造 Goal、不把 VP 改成 blocked | 入口边界核对 |
| U09 | 已 done/cancelled 的 Goal 或独立审计角色 | 不自动 reopen、不由审计员改 Goal 状态；交编排侧处理待答；任务停止 | 角色边界/fixture |
| U10 | blocked/goal-tree 写盘失败或重启后恢复 | 仍停止；明确未持久成功；重启先读待答问题，禁止静默继续 | 故障 fixture + 重启验证 |
| U11 | 用户真实提交选择/明确自由文本答复 | 对照原问题核对适用范围，写真实决定，重新检查其他门禁；不直接 done | 当前宿主实际交互 + ledger |
| U12 | tool exit 0 / SDK allow / 代理说“用户已同意”但无提交来源 | 不能作为答复事实，继续保持等待 | 反例/问答证据 |

通过阈值：规范与所有发货入口无相反条款；适用代码路径的正反例全部通过；实际宿主证据明确产品/版本/模式/输入输出及结论边界。静态文本匹配不证明宿主 UI 行为；模拟空结果不冒充真实 UI 取消。无法验证的项保持开放或按 P-004 请求有范围的用户裁决，不静默删例或降级。
