# D-002 · S1 证据闭合条文与复现，占位符策略不在本条冻结（2026-09-30）

**状态**：accepted

**触发**：S1 退出条件要求两条反馈都有可核对的失败模式，或明确的负结果。证据在 [s1-failure-modes-2026-09-30.md](../attachments/s1-failure-modes-2026-09-30.md)。

## 决定

1. **I-001 改为 `verified`。** 死锁来自现行门禁没有区分「只有做完该项工作才存在的结论」和「工作开始前已经可以核对的事实」。条文位置与两条反例写在附件 §1。这不改原则正文；S2 要同时放行研究结论死锁反例，并保留先于执行的事实仍可设门禁。
2. **I-002 改为 `verified`。** 负结果：`install.sh` / `install.ps1` 都不能传入方法论目录，核心方法论写死安装到 `./docs/` 或 `.\docs\`；`--skills-dir` 可以指定 skills 目录；安装器不替换占位符。正结果：在受管块和受管 `docs/architecture/principles.md` 里替换占位符后，`modified_managed_files` 列出 2 个路径；与包内源一致时列出 0 个。`update_package` 在该列表非空且没有 `--force-managed` 时抛出 `managed files have local changes`。完整 `update_package` 没有跑，因为它会下载 Release。
3. **I-003 保持 `open`。** 附件 §2 记下了模板第 15 行的默认 `docs` 定义，以及安装副本没有这句。用户原话仍在「尤其是让ai从」处截断。此项只阻断「不替换占位符」这一支的冻结。
4. **I-004 改为 `verified`。** 用户在本会话书面指定：交叉审计调用本地 codex CLI，模型 `gpt-6.1-sol`，思考强度 `high`。审计还没有跑。CLI 失败、超时或不能以该模型与强度给出可核对意见时，门禁保持未满足，不降级，也不由编排器写成 independent。
5. **不另开子目标。** 用户书面规则是「如有必要，请渐进开设子目标承载治理上下文（无必要则不开）」。S1 看到的是同一目标里的两个阶段：S2 改规则文本，S3 改安装与升级。写集不同，但没有出现必须拆出才能取证或关门的范围、依赖或证据链。
6. **占位符策略不在本条冻结。** S3 在用户选定之前不改安装器、不改 `update.py`。S2 的规则语义已由本目标成功标准和本条的两条反例限定，不依赖这条策略。

## 为什么

- D-001 要求 S1 先核对，再改协议或安装。附件里的行号和复现输出满足这个退出条件。
- I-004 的问题是「provider 是谁」。用户指令已经写明工具、模型和思考强度，这项信息已经有书面答案。
- 两条问题仍能在 GOAL-009 的 S2 / S3 里分别验收。现在拆开会把用户已经指定的一个目标再拆成一层，S1 没有显示这一层是关门所必需的。

## 未选方案

| 方案 | 未选理由 |
|------|----------|
| 本条顺手改 P-005 或 update | S1 的退出条件是只记证据。规则文本属于 S2，占位符行为还没有用户选定 |
| 把「不替换则按默认 docs」直接当成选定不替换 | 这只证明自定义目录下不替换会指错路径。截断句未补全，不替换分支不能冻结 |
| 因写集不同就另开 GOAL-010 | 与用户「无必要则不开」不一致；本目标路线图已经把两段分成 S2 和 S3 |
| 在 provider 未跑审计前把 I-004 留到实施当天再认 | 用户已经书面指定。留着 open 会把「谁来审」和「审过没有」混成同一个门禁 |

## 仍待用户决定

安装与升级对受管占位符采用哪一条，本条不代选：

- 安装时按指定的方法论目录和 skills 目录渲染占位符，升级按这次渲染比较，替换本身不算本地改动。今天没有方法论目录参数，这一支需要补上。
- 只让 update 接受已经替换过的受管文件，不新增方法论目录参数。
- 不替换占位符，另给 AI 路径锚点。选定前要先补全「尤其是让ai从」。
