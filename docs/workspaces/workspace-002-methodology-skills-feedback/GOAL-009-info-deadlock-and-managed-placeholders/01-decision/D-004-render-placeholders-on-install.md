# D-004 · 安装时渲染受管占位符，升级按双基线比较（2026-09-30）

**状态**：accepted

**触发**：用户于 2026-09-30 书面选定占位符策略，并书面拒绝「不替换」分支。S3 可以按这条冻结实施。本条不包含安装器提交，也不把 GOAL-009 标为 `done`。

## 决定

1. **采用安装时渲染。** 安装增加方法论目录参数（`install.sh --methodology-dir`，默认 `./docs`；`install.ps1 -MethodologyDir`，默认 `./docs`；GNU 形式同名）。核心方法论安装到该目录，不再写死 `./docs/`。`--skills-dir` / `-SkillsDir` 仍指定 skills 目录。两个参数都收成项目内相对 posix 路径：去掉 `./`，拒绝空路径、`..` 和项目外绝对路径；落在项目内的绝对路径改写成相对路径。
2. **受管占位符按这一次的两个目录替换。** `{{GOVERNANCE_ROOT}}` 与 `{governance_root}` 换成方法论目录；`{{CORE_TEMPLATES_DIR}}` 换成 `{方法论目录}/templates`；`{{SKILLS_DIR}}` 换成 skills 目录。`{{GOAL_FOLDER_TEMPLATE}}` 保持原样，避免把它误判成冲突。渲染只发生在消费方目的地：方法论树、`.claude/skills`、`.grok/skills`、`.agents/skills`、`.github/prompts`、`.github/copilot-instructions.md`。不改技能包源码，也不就地改写消费方 `AGENTS.md` 整份文件；受管块用临时渲染副本再合并，标记外字节不改。没有 Python 3.8+ 时渲染失败并停止。
3. **升级比较使用双基线。** 用户要求：升级按这次渲染结果比较，替换本身不算本地改动，真正的手改仍然 fail closed。只拿「本次渲染字节」做唯一对照，会把尚未重装、仍等于包内原文的旧安装全部看成手改。因此干净的定义是：目的地字节等于包内原文，或等于本次给出的方法论目录与 skills 目录渲染后的字节。其他差异仍是手改，没有 `--force-managed` 时 `update_package` 继续抛出 `managed files have local changes`。升级若用了与安装不同的目录，渲染期望对不上，同样 fail closed。根 `AGENTS.md` 沿用同一规则：受管块等于渲染后的源，或等于未渲染的源，都不是冲突；合并时写入渲染后的源，避免把已渲染的块盖回占位符。
4. **I-003 改为 `verified`。** 该项只阻断「不替换占位符」分支。用户书面选择「不走这条分支」，截断句「尤其是让ai从」不再需要补全。这不是「不替换时 AI 能否认路」的实测结论。
5. **不另开子目标。** S1 没有出现必须拆出的范围。策略选定后，安装与升级仍是本目标 S3 的实施切片。
6. **双基线是本条写下的兼容后果，不是另一次用户选择。** 若随后的独立审计认为它必须再经用户确认，停止放行并询问。本条不把该确认写成已经发生。

## 为什么

- 用户选定的是「给安装增加方法论目录参数，按这次指定的两个目录渲染，升级按这次渲染比较」。今天的安装器不能传入方法论目录，所以这一支必须补参数，不能只改比较函数。
- 默认目录仍是 `docs` 与 `skills`。不传新参数时，安装位置与现有调用保持一致。
- 旧安装器写出的是未替换字节。把这些字节继续视为干净，替换本身才不会被升级当成手改，已经手改的文件也不会被放行。

## 未选方案

| 方案 | 未选理由 |
|------|----------|
| 只让 update 接受已替换文件，不新增方法论目录参数 | 用户选定的是安装按指定目录渲染。没有该参数，自定义方法论目录无法成为渲染输入 |
| 不替换占位符，另给路径锚点 | 用户书面拒绝这一支 |
| 升级只接受本次渲染字节，不接受包内原文 | 会把所有尚未重装的旧消费方判成本地改动。用户要求替换本身不算本地改动 |
| 本条提交一并包含安装器改动 | 方案冻结与实施切片分开留痕。工作区里已有未提交的安装器改动，它们不属于本条 |
