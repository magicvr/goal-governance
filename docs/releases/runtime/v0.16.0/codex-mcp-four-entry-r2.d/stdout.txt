审计模式 / provider 无法唯一确定 | 按风险选择 `none` / `self` / `independent` / `cross`；仅 independent/cross 已确定且会话与项目配置都无 provider，或风险分级实质歧义时询问 |\r\n| 多条意见在结论/必改项上冲突 | 展示冲突 + **给建议** + **等用户决策**并留痕；未决不放行/不关门 |\r\n| 单条（或无冲突）required finding 要否决/residual | 停止放行；说明风险；等用户选 fixed / residual / overruled 并留痕（P-003） |\r\n| 信息 residual、有界实验、信息冲突 | 按 P-005 字段要求问用户并留痕；不得静默推断 |\r\n\r\n已有 independent 而无 self 不再单独触发询问：`independent` 不固定要求 self，`cross` 必须有 self。required finding、冲突、residual / overruled 与信息冲突仍必须由用户裁决。\r\n\r\n### 用户询问与缺答暂停（UI-01～UI-06）\r\n\r\n停止对象是宿主原生 `/goal` / 自动续跑或当前执行。同步卡片要实际调用并等待；卡片不能持续挂起时组合使用实际可用且符合工具契约的原生停止能力。**无需另次确认**，但不能绕过原生状态工具的阈值、用户授权等前置条件。等待不自动改变治理 Goal 状态，也不要求额外写执行索引、目标树或父级投影。\r\n\r\n全文 `{governance_root}/architecture/principles.md#user-input-wait`。有可用且允许的同步阻塞询问卡片时必须使用；选择题给 2～3 个互斥方案、AI 推荐及取舍，保留自由输入。卡片不可用/用途受限/headless 无真人答复通路时文本提问并停止，不以异步询问替代阻塞。\r\n\r\n发问后暂停当前执行；空答复、取消/关闭/超时、缺题、答非所问、预选未提交或仅展示成功均不是答复，不补默认、不虚构。原题/选项与待答保留在会话中即可；只有交接或必需治理证据才保留一次最小记录。无 Goal 仍等待，不为等待新造或组合目标，VP 不改 blocked；治理真实交付阻塞另行判断。无原生停止能力时如实报告，并提示用户暂停/中断，不冒称已控制宿主。\r\n\r\n空卡片返回后停止，不继续实施/放行/关门或其他工作，不将沉默当 residual/overruled。自动续跑先检查会话待答并保持合法停止，不轮询重问或重复写盘；真实答复逐题核对后复核全部门禁与其他阻塞，只继续已解决范围，不自动恢复治理 active/done 或用户主动暂停的原生目标。独立审计只在自身权限记录实际意见。必要写盘失败时仍停止，不能据此绕过未答门禁。\r\n\r\n### P-005 · 信息就绪与未知项门禁\r\n\r\n- **允许带未知立项**：目标不必在设立时已知所有信息；但必须能写明意图、初始边界、父级与最小可验证方向。已识别的未知、假设或待验证事实不得伪装为决策、成功事实或已关闭风险。\r\n- **信息需求登记**：在目标的 `00-meta.md` 或 `01-decision.md` 维护信息项，至少含：编号、要回答的问题/所需信息、`required` 或 `non-blocking` 级别、影响的决策或门禁、最晚需要阶段、验证/收集动作、状态、延期/复核和证据或结论。`deferred` 必须有延期理由、责任人和下一复核日期或触发条件。\r\n- **阶段门禁**：影响方案冻结、实施、验收或关门的 `required` 信息项，必须在对应阶段前由证据关闭。经用户裁决并记录的有界实验只可进入明确的信息收集范围，信息项仍为 `collecting`；唯一能解除明确门禁的例外是用户书面接受的、有范围和复审触发条件的残余风险，接受不等于信息已经验证。\r\n- **结果尚不存在时**：某个 required 信息项只有做完它要挡住的那项工作才有答案，则它不是进入该项工作的门禁。调查、研究或澄清本身就是这项工作时，做这项工作就是在收集该信息。工作开始前已经可以独立查询或核对的事实，仍然可以是进入执行、发布或验收的 required 门禁。\r\n- **发现后的回流**：实施中发现新的关键未知时，暂停受影响范围，记录事实，并回到信息登记、决策或路线图；信息冲突、是否以有界实验收集信息、或是否接受残余风险由用户按 P-004 裁决。到达最晚需要阶段时，未获 residual 接受的 `deferred required` 视为开放 required 并阻断受影响门禁。\r\n- **按规模拆分**：先登记并设定门禁；只有澄清/收集工作具有独立范围、依赖、交付证据或并行价值时，才创建“信息澄清/验证”或“信息收集”子目标。禁止为每个低风险问题机械创建两个子目标。\r\n\r\n## 6c. 工作区与共享资料边界\r\n\r\n先定位当前 `{governance_root}/workspaces/workspace-<NNN>-<slug>/workspace.md`，再按
